
# Cache Locality 缓存局部性（放到 Trae 文档，面试直接背）

## 一句话概括

CPU 访问内存很慢，所以硬件把常用数据提前放到高速缓存（Cache L1/L2/L3）。
**Cache Locality = 数据访问的“就近程度”**。访问的数据越集中、连续，缓存命中率越高，代码跑的越快；跳来跳去随机读内存，大量 Cache Miss，代码直接慢几倍~几十倍。

> 核心口诀：**CPU 不爱随机跳着读内存，喜欢连续顺序读**

## 两种局部性

1. **空间局部性（最常用，运动规划/点云重点）**
   当你访问内存地址A，硬件会**把A附近一整块内存（Cache Line，一般64字节）一次性加载进Cache**。
   如果你接下来访问A旁边的数据，直接在Cache拿到，很快；
   如果你读完A，马上跳到很远的地址，这块Cache Line白加载 → Cache Miss，要去慢速内存读取。

例子：
数组顺序遍历：`arr[0], arr[1], arr[2]` → 空间局部性好 ✅
数组乱序随机跳：`arr[0], arr[1000], arr[5]` → 空间局部性差 ❌

2. **时间局部性**
   **最近刚读过的数据，大概率短期内还会再次用到**，保留在Cache里复用。
   比如循环里反复读取同一个变量，时间局部性很好。

> Cache Line：最小缓存单元，通常64字节。一次加载就是加载一整行。
> Cache Miss：想要的数据不在Cache，必须去读主内存，延迟很高。

## 在这个运动规划岗位，什么时候会遇到Cache Miss？

岗位里的 ESDF、KDTree、点云、碰撞查询，最容易踩坑：

- KDTree遍历节点，节点在内存零散分布，查询时到处跳内存 → 大量cache miss
- ESDF体素网格，如果内存布局乱，查询距离的时候不断跨Cache Line
- AoS 结构体数组，循环只读取x坐标，但是内存里x,y,z穿插在一起，每次读x都顺带把y,z加载进来，浪费带宽，cache利用率低

## 工程上怎么优化 Cache Locality（面试必说，你的简历关键词）

### 1. AoS → SoA 改造（最高频！和SIMD配套）

AoS：`struct Point{float x,y,z;} points[];`
内存：x0 y0 z0 x1 y1 z1 x2 y2 z2
遍历只读取所有x的时候，每读一个x，Cache还会把没用的y,z加载进来，浪费缓存空间。

SoA：分开数组 `float x[], y[], z[];`
内存：x0 x1 x2 x3 … 连续放，y单独一块，z单独一块
批量读取x的时候，连续内存，Cache利用率拉满，非常适合SIMD。

> 点云、ESDF网格、批量采样，优先SoA布局。

### 2. 保证数据连续分配，减少碎片化

- 使用连续容器：`std::vector`（连续内存），不要大量零散new单个对象（new出来的对象内存地址分散）
- 内存池预分配：一次性申请一大块内存，自己管理，避免零散分配造成内存碎片

### 3. 改变遍历顺序，尽量顺序访问，消灭随机内存访问

比如KDTree：尽量把树节点在内存里做**线性化布局（flat tree）**，而不是用指针左右子节点（指针会跳到随机内存）。

> 原始KDTree用指针：node->left，node->right，每次跳转地址随机，cache爆炸。工程优化就是把树拍平成数组，用索引代替指针。

### 4. 内存对齐 alignas

让数据起始地址对齐到Cache Line边界，避免一个数据横跨两条Cache Line（跨行访问会读两次Cache Line）

```cpp
struct alignas(64) Voxel {
    float dist;
};
```

### 5. 分块 / tiling（分块遍历）

如果超大矩阵/网格，一次性遍历整个大数组放不下进Cache。把数据切成小块，一小块处理完再下一块，让当前块全部驻留在L1/L2 Cache。ESDF计算常用tiling。

### 6. 减少不必要的数据加载

循环里面只加载计算必须的字段，不要把一整个大结构体全部读入缓存。

## 面试标准答案（直接背诵）

> Cache Locality分为空间局部性和时间局部性。CPU会按Cache Line加载内存数据。如果代码随机访问内存，会产生大量Cache Miss，触发慢速主内存访问，性能大幅下降。
> 优化手段：优先顺序遍历；把AoS改成SoA；使用vector/内存池保证数据连续；对数据做内存对齐；大的数据使用tiling分块；把树结构线性化，用数组索引代替裸指针，减少随机跳转。这个优化思路在ESDF、KDTree这类空间查询数据结构中非常关键。

## 区分：Cache Locality（CPU） vs CUDA Global Memory

- CPU Cache Locality：L1/L2/L3缓存，优化思路是连续访问、减少随机跳转
- CUDA Global Memory：GPU显存，优化思路是**合并内存访问（coalesced memory access）**，概念很像，但硬件机制不一样。面试官有时候会对比提问。
