
# 循环展开 Loop Unrolling（放到Trae文档，面试精简版）

## 一句话解释

**循环展开：减少循环的“簿记开销”，一次循环迭代，一次性处理多份数据，而不是只处理1个。**

循环本身有额外开销：每次循环要做：判断条件、自增索引、跳转。
循环展开就是**减少循环跳转次数**，同时给编译器更好机会做SIMD向量化。

## 原始未展开（unroll=1）

```
for(int i=0; i<N; i++){
    out[i] = in[i] * 2.0f;
}
```

每次循环：i++、判断 i<N、跳转，只算1个元素。

> 循环控制指令占开销，大量小循环会浪费CPU算力。

## 手工展开2倍 unroll=2

```
for(int i=0; i<N; i+=2){
    out[i]   = in[i] * 2.0f;
    out[i+1] = in[i+1] * 2.0f;
}
```

i 每次+2，**一次迭代处理2个元素**，循环跳转次数减半。

展开4倍 unroll=4：一次迭代处理4个元素，循环跳转变成原来1/4。

## 两种形式

1. **手工循环展开**：程序员自己手写多份计算语句
2. **编译器自动展开**：`#pragma GCC unroll 4`，让编译器帮你做，工程里更常用

```
#pragma GCC unroll 4
for(int i=0; i<N; i++){
    out[i] = in[i] * 2.0f;
}
```

## ✅ 和SIMD、cache locality的关系（面试重点，运动规划场景）

循环展开**本身不是SIMD**，但经常配套一起使用：

- 展开后，连续多条独立浮点计算，编译器更容易自动向量化（SIMD）
- 配合SoA内存布局，连续访问内存，提升cache命中率

> 运动规划场景使用地方：批量距离计算、ESDF体素遍历、碰撞检测批量校验。

## ⚠️ 代价和坑（面试官喜欢问缺点）

1. **代码体积变大**（代码膨胀），指令太多，反而挤占L1指令Cache，造成icache miss，性能下降。不是展开越大越好，一般unroll 2/4足够，不要无脑unroll 16、32。
2. 边界处理麻烦：总数N不是展开倍数整数倍时，需要写尾部剩余元素处理。
3. 如果循环内部计算有依赖（后面计算依赖前面结果），展开收益很小。
4. 现代编译器很聪明，简单循环会**自动unroll**，很多时候不用手写；手写主要针对底层高性能模块、SIMD优化场景。

## 面试背诵短句

> 循环展开，就是在单次循环迭代中处理多个数据，减少循环条件判断和跳转的开销；同时方便编译器做SIMD向量化。但会增加代码体积，过度展开会造成指令Cache失效，一般2~4倍展开比较常用。常和SoA、cache局部性优化搭配，用于批量距离、碰撞这类计算。

## 区分几个容易混淆名词

- **Cache locality**：优化**数据内存访问**
- **SIMD**：单指令一次性算多份数据
- **Loop unrolling**：减少循环跳转开销，辅助SIMD

> 小提示：CUDA里面也有循环展开，原理一样，减少kernel内循环开销。

# 循环展开：尾部剩余处理（Trae文档，带可阅读C++示例）

> 场景：**unroll 4**，每次循环一次性处理4个元素。
> 如果总元素数量 `N` 不是4的整数倍，最后会剩下 `0/1/2/3` 个元素，这部分就是**尾部残差**，需要单独处理。

## 方案1：标准写法（先跑主循环，最后单独处理尾部，最常用）

```
// unroll 4版本
void scale(float* __restrict out, const float* __restrict in, int N)
{
    int i = 0;
    // ========== 主循环：一次处理4个 ==========
    for (; i <= N - 4; i += 4)
    {
        out[i]   = in[i] * 2.0f;
        out[i+1] = in[i+1] * 2.0f;
        out[i+2] = in[i+2] * 2.0f;
        out[i+3] = in[i+3] * 2.0f;
    }

    // ========== 尾部残差循环：剩下不足4个 ==========
    for (; i < N; i++)
    {
        out[i] = in[i] * 2.0f;
    }
}
```

### 原理

- 主循环条件：`i <= N-4`，保证每次 `i+3` 不会越界；
- 当剩下元素 <4，退出主循环；
- 尾部普通标量循环逐个处理剩下1/2/3个元素。

优点：代码干净，**不用写一堆if分支**，工业底层代码常用；
缺点：尾部没法SIMD，但是数据量很小，开销可以忽略。

---

## 方案2：完全手动展开尾部（完全不使用尾部for循环，极致手工unroll）

适合追求极致性能、不想保留小循环：

```
void scale(float* __restrict out, const float* __restrict in, int N)
{
    int i = 0;
    for (; i <= N - 4; i += 4)
    {
        out[i]   = in[i] * 2.0f;
        out[i+1] = in[i+1] * 2.0f;
        out[i+2] = in[i+2] * 2.0f;
        out[i+3] = in[i+3] * 2.0f;
    }

    // 尾部手工分支处理
    if (i < N) { out[i] = in[i] * 2.0f; i++; }
    if (i < N) { out[i] = in[i] * 2.0f; i++; }
    if (i < N) { out[i] = in[i] * 2.0f; i++; }
}
```

> 依次判断，最多跑3条。
> 面试时：**知道这个思路即可，工程一般优先方案1**。

## unroll=16 的例子（一次性处理16个元素）

```
void scale_unroll16(float* __restrict out, const float* __restrict in, int N)
{
    int i = 0;
    // 主循环：一次处理16个
    for (; i <= N - 16; i += 16)
    {
        out[i]    = in[i] *2.0f;
        out[i+1]  = in[i+1] *2.0f;
        out[i+2]  = in[i+2] *2.0f;
        out[i+3]  = in[i+3] *2.0f;
        out[i+4]  = in[i+4] *2.0f;
        out[i+5]  = in[i+5] *2.0f;
        out[i+6]  = in[i+6] *2.0f;
        out[i+7]  = in[i+7] *2.0f;

        out[i+8]  = in[i+8] *2.0f;
        out[i+9]  = in[i+9] *2.0f;
        out[i+10] = in[i+10] *2.0f;
        out[i+11] = in[i+11] *2.0f;
        out[i+12] = in[i+12] *2.0f;
        out[i+13] = in[i+13] *2.0f;
        out[i+14] = in[i+14] *2.0f;
        out[i+15] = in[i+15] *2.0f;
    }

    // 尾部：不足16个，逐个处理
    for (; i < N; i++)
    {
        out[i] = in[i] * 2.0f;
    }
}
```

## ✅ 重要知识点（面试必问）

### 1. `__restrict` 关键字

告诉编译器：**这个指针是这块内存唯一引用**，没有别名。编译器可以大胆做向量化、循环展开优化。高性能C++常用。

### 2. 编译器自动展开（推荐优先使用，不用手写大量重复代码）

```
#pragma GCC unroll 4
for(int i=0; i<N; i++){
    out[i] = in[i] * 2.0f;
}
```

编译器自动处理主循环+尾部残差，**工程首选**。

> 手写unroll只用于：非常核心的底层hot loop，编译器自动优化达不到预期的场景。

### 3. 坑点

1. **不要无脑unroll 16、32**：会造成代码膨胀，指令cache爆满，性能反而下降。
   运动规划里面批量距离计算，一般unroll 4足够。
2. 循环内**存在数据依赖**（后面计算依赖前面结果）：循环展开几乎没有收益。
3. 越界风险：主循环条件 `i <= N - unroll_factor` 不能写成 `i < N-unroll_factor`，会少跑一轮。

## 面试一句话总结

> 循环展开一般分成两段：主循环一次性处理K个元素，循环条件保证不会越界；剩下不足K个元素用尾部循环或者分支单独处理。工程上优先使用`#pragma GCC unroll`交给编译器自动展开，手工展开只用在核心热点循环。

## 补充：CUDA kernel里循环展开写法（顺带记，岗位CUDA相关）

CUDA里思路一模一样，在kernel内部循环展开：

```
__global__ void scale_kernel(float* out, const float* in, int N)
{
    int idx = blockIdx.x * blockDim.x + threadIdx.x;
    int i = idx;
    for (; i <= N-4; i +=4)
    {
        out[i]   = in[i] * 2.0f;
        out[i+1] = in[i+1] *2.0f;
        out[i+2] = in[i+2] *2.0f;
        out[i+3] = in[i+3] *2.0f;
    }
    for (; i<N; i++){
        if(i<N) out[i] = in[i]*2.0f;
    }
}
```
