# AGENTS.md — render_project 项目 AI 代理指南

> 本文件由 AI 代理（Trae 等）在每次会话开始时自动读取。
> 遵守本文件可确保知识库持续生长、风格统一。

## 1. 项目定位

3D 渲染知识体系库（光栅化 / 光追 / OpenGL / Vulkan / VTK / Shader / 3DGS）。
服务于两个目标：
- 求职面试（每个知识点配"30 秒面试讲法"）
- 工程选型能力（每个技术配"什么场景用什么"决策节）

## 2. 沟通规则

- 与用户交流使用中文
- 教学风格：深入浅出、生活类比先行、具体数字说话，**不讲抽象空话**
- 每个概念必须回答：是什么 / 为什么 / 什么时候用

## 3. 核心协议：对话精华沉淀（最重要）

**每次对话中用户讲授、确认、补充、纠错的知识，必须写入文档库。**
对话是知识的一手来源，不沉淀 = 白聊。

### 3.1 什么时候触发写入（会话结束前自查）

命中任一即写入：

- 用户发来大段学习笔记/心得（如"Shader 和 OpenGL 的关系"）→ 整段吸收
- 用户对某个概念提出自己的理解且被确认正确 → 记录表述（往往比原文档更好懂）
- 用户指出文档错误 → 修正并在自检问答中补一条"易错点"
- 用户提出好问题（即使已在对话中回答）→ 转化为文档自检问答
- 对话中产生了新类比、新口诀、新工程经验 → 收进对应文档

### 3.2 写哪里（选择顺序）

1. **优先嵌入已有文档的对应章节**（追加小节/表格/自检问答）
2. 已有文档放不下/主题独立 → 新增文档（编号顺延，如 09/10/…）
3. 无论哪种方式，README.md 的文档地图必须同步更新

### 3.3 写入标准

- 保留用户的原始类比和口诀（那是用户自己的记忆锚点，比标准术语有价值）
- 补全"来龙去脉"和"边界条件"，不只抄对话
- 每次写入后在 git commit message 中说明新增/修改了什么知识点

## 4. 文档写作规范

每篇文档标配（参考现有 09 篇）：

| 段落 | 作用 |
|---|---|
| 故事/类比导入 | 先给直觉再给术语 |
| 概念+具体数字 | 不讲抽象，用真实量级（如"1080p≈200万像素"） |
| 工程取舍 | 什么场景用什么、为什么 |
| 面试讲法（30 秒） | 可直接背诵的口语版 |
| 自检问答 | 3~6 道，覆盖易错点 |

其他规范：
- 与 cuda_project 挂钩的概念要交叉引用（如 BVH↔uniform_grid、warp↔quad）
- 类比体系保持一致：盖章/侦探/实习生/贴纸/钉子（见 09 篇）
- 严禁只贴链接不写内容——文档要自包含

## 5. Git 提交格式

```
[<module>][<type>] <subject>
```

- module：`docs`（文档新增/修改为主）
- type：`feat`（新文档/新章节）| `fix`（纠错）| `chore`（索引/格式）
- subject：小写祈使句，说明知识增量（如 "add shader-opengl relationship notes"）
