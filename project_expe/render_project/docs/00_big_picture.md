# 00 — 3D 渲染全景：屏幕上的 3D 是一场数学骗局

## 一、先想清楚：屏幕是平的，3D 哪来的？

你的显示器只有两个维度：横向 1920 个像素、纵向 1080 个像素。
所谓"3D 游戏"，本质是**每帧回答同一个问题**：

> 摄像机在 P 点朝 D 方向看，屏幕上每个像素应该是什么颜色？

注意这个问题的形态：**输入是几何（3D 物体）+ 摄像机，输出是一张 2D 图**。
渲染（rendering）= 求解这个问题。所有渲染技术只是"求解策略"不同。

## 二、所有 3D 渲染共同的数学地基：MVP 变换

不管光栅化、光追还是 3DGS，第一步都是把 3D 坐标搬到屏幕上，分三步：

```
世界坐标 ──(Model)──→ ──(View)──→ ──(Projection)──→ 屏幕坐标
"物体在哪"    "摄像机看它"    "压扁成照片"      "第几行第几列"
```

**生活类比：给雕塑拍照片**
- **Model 变换**：把雕塑摆到摄影棚的台子上（物体自己的位置/旋转/缩放）
- **View 变换**：换个说法——不动雕塑，把整个摄影棚搬走，让雕塑站在镜头正前方。数学上等价于"把摄像机搬到原点"，为什么这么绕？因为这样后面的投影公式最简单（z 轴就是"往里看"）
- **Projection 变换**：透视投影——远小近大。平行的铁轨在照片里会相交于一点，这个"近大远小"用 4×4 矩阵一次性完成（这就是为什么图形学全用 4 维向量 [x,y,z,1]——第 4 维 w 就是干除法透视用的）

**关键体感**：MVP 之后，一个 3D 点变成屏幕上的一个 2D 点 + 一个深度值。
渲染的所有流派都从这一步出发，分歧在"接下来怎么算颜色"。

## 三、两大流派：涂屏幕 vs 问世界

### 流派 A：光栅化（Rasterization）—— "从物体出发"

> 拿起三角形，像**盖章**一样把它"啪"地盖在屏幕上，章覆盖的每个像素填上色。

- 方向：物体 → 屏幕（顺着光路"投影"）
- 天然并行：每个三角形独立盖、每个被盖的像素独立填色
- 弱点：**只回答"这里有没有东西"，不回答"光是怎么传播的"**——反射、折射、软阴影全靠人肉数学技巧伪造（详见 01）

### 流派 B：光线追踪（Ray Tracing）—— "从像素出发"

> 屏幕上每个像素，从摄像机**反向发射一条光线**，看它打到哪个物体、
> 这个物体又反射/折射到哪，物理正确地算出颜色。

- 方向：像素 → 物体（逆着光路"求解"——光路可逆，物理等价但好算）
- 天然真实：反射里能看到镜子、玻璃后面能看到东西——不是伪造，是模拟
- 弱点：**每条光线要和全场每个物体求交**，贵到爆（详见 02）

### 一张表看懂 40 年战争

| 维度 | 光栅化 | 光线追踪 |
|---|---|---|
| 出发点 | 物体投到屏幕 | 屏幕问世界 |
| 并行度 | 极高（像素独立） | 高（光线独立），但单条贵 |
| 真实感 | 要靠技巧伪造 | 物理正确自然涌现 |
| 速度 | 实时（144fps 游戏） | 离线（电影渲染农场）或半实时 |
| 典型用户 | 游戏/CAD/点云 | 电影/建筑效果图 |
| 硬件 | GPU 的主业 | RT Core 专用芯片（2018 起） |

**历史线**（来龙去脉）：
- 1980s：光追理论成熟（Whitted 1980），电影业悄悄用；游戏机太弱只能光栅化
- 1999：NVIDIA 把光栅化管线做成硬件，"GPU"这个词诞生
- 2018：NVIDIA RTX——把光追求交做成专用电路，游戏开始实时光追
- 2023：3DGS——第三条路，"高斯雪球泼墨"，训练+实时渲染重建场景（详见 07）

## 四、API 和框架：谁在指挥 GPU

上面是"算法层"。往下还有两层，名字最容易混：

```
你的代码
  │
  ├── API 层（怎么跟 GPU 说话）
  │     OpenGL (1992)   — 老将，驱动帮你做决定
  │     Vulkan (2016)   — 新贵，什么都要自己写
  │     DirectX (微软) / Metal (苹果) — 平台亲儿子
  │     CUDA (2006)     — 通用计算，不管图形只管算力
  │
  └── 框架层（在 API 之上帮你搭好房子）
        VTK — 科学可视化（医学影像/CFD/点云）
        Unity/Unreal — 游戏引擎（场景/物理/资产全管）
        Ogre/three.js — 轻量渲染库
```

**一个必考的区分**：
- OpenGL/Vulkan 是**指挥 GPU 的说明书**（画三角形、上传纹理、跑 shader）
- VTK/Unity 是**盖好的房子**——VTK 内部调 OpenGL，Unity 内部可切 OpenGL/Vulkan/DX
- 所以"VTK 和 OpenGL 选哪个"是个错误问题（层级不同），正确问法是"我要不要框架帮我管场景"

## 五、Shader：绕不开的中间件

无论走哪条路（3DGS 除外，它走 compute shader），现代渲染的管线中间都插着
**你写的小程序——shader**（详见 06）。它是"固定流水线"进化成"可编程流水线"的产物：

> 1995 年前：GPU 硬件焊死每个步骤怎么算（能调参数，不能改逻辑）
> 2001 年起：顶点和像素的处理逻辑开放给你写代码 → shader 诞生
> 今天：CUDA 本质上是"把 shader 泛化到任意计算"

## 六、自检问答

1. **Q: 渲染问题的输入输出是什么？**
   A: 输入 = 3D 几何 + 材质 + 光源 + 摄像机；输出 = 每个像素的颜色。

2. **Q: MVP 各自干什么，为什么 View 要倒着搬世界？**
   A: Model 摆物体、View 把摄像机变到原点看 -Z、Projection 压扁。倒搬世界是为了让投影公式退化到最简形态——数学等价但计算便宜。

3. **Q: 光栅化和光追的最本质区别一句话？**
   A: 光栅化顺着投影"涂屏幕"（快、假），光追逆着光路"问世界"（慢、真）。

4. **Q: OpenGL 和 VTK 是竞争关系吗？**
   A: 不是，分层关系。VTK 是框架，内部用 OpenGL 当渲染后端。
