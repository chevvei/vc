# 08 — 决策地图：什么场景用什么技术

> 本篇是收口：不背概念，只回答"给我一个场景，我选什么、为什么"。
> 面试聊选型 = 展示工程判断力的最快方式。

## 一、总决策表（背这张）

| 你的场景 | 选 | 一句话理由 |
|---|---|---|
| 游戏实时画面 | 光栅化为主 + 光追特效 | 60fps 铁约束；光追只补反射/全局光 |
| 电影级离线渲染 | 路径追踪（离线） | 物理正确第一，一帧几小时可接受 |

| 科学数据三维图（CT/CFD/FEM） | VTK（Python/C++） | Filter 流水线 + 体绘制开箱即用 |
| 网页 3D 展示 | three.js / WebGPU | 生态在浏览器，零安装 |
| 游戏引擎开发 | Vulkan（Win/Android）/ Metal（苹果） | 多线程录制 + 性能确定性 |
| GPU 通用计算（非图形） | CUDA | 和图形 API 平行的赛道，厂商深度优化 |

| 实时大场景光照模拟（机器人仿真） | 光栅化 + 探针烘焙 | Isaac Sim/Omniverse 的实际做法 |

## 二、三层技术速答卡（面试 10 秒版）

**渲染算法层**（怎么算颜色）：
- 光栅化：物体→屏幕投影涂色。快、可并行、光照靠伪造。实时主赛道。
- 光线追踪：像素→世界求交递归。真、贵、靠 BVH 剪枝。电影 + RTX 游戏。
- 3DGS：高斯雪球排序叠加。照片级实时，重建领域新王。

**API 层**（怎么指挥 GPU）：
- OpenGL：状态机，驱动兜底，简单。1992 年生，工具/科研仍主力。
- Vulkan：显式控制，pipeline 不可变 + command buffer 多线程。1500 行三角形，引擎级选择。
- （CUDA：不是图形 API，是计算 API，但同代"显式哲学"，和 Vulkan 的 stream/fence 概念一一对应。）

**框架层**（谁帮你搭好房子）：
- VTK：数据流水线（Source→Filter→Mapper→Actor），科学可视化。
- Unity/Unreal：场景图 + 物理 + 资产工作流，游戏/仿真。
- three.js：浏览器轻量场景。

## 三、高频对比题标准答案

**Q1: OpenGL 和 Vulkan 怎么选？**
> 看负载性质。工具/科研可视化（点云、CAD）选 OpenGL：场景简单，
> 性能上限碰不到，1500 行 Vulkan 纯属负债。引擎级负载（数千 draw call、
> CPU 提交瓶颈、多线程录制收益）选 Vulkan：pipeline 不可变换来运行时
> 零验证，command buffer 并发录制吃满多核。我的点云渲染经历是
> Qt+OpenGL 手写——那个量级 OpenGL 是正解。

**Q2: 光追会取代光栅化吗？**
> 不会，是分工。直接可见的绘制光栅化已是理论最优（每像素恰好一次
> 投影），光追的不可替代区是光的二次传播（反射/ GI/阴影）。现代引擎
> 是混合管线：光栅化打底、光追点睛、AI 降噪+超分补帧。硬件也是按
> 混合设计的（rasterizer + RT core + tensor core 三件套）。

**Q3: NeRF 和 3DGS 的本质区别？**
> 表示方式。NeRF 隐式：场景信息在 MLP 权重里，每个像素要过网络查询
> （慢但连续性好）。3DGS 显式：百万个高斯参数直接摆在那，渲染=投影
> +排序+混合的 CUDA 流水线（快、可编辑、可传统图形管线融合）。
> 外观上 3DGS 用球谐系数（48 个数）替代了 NeRF 的网络输出——
> 显式压缩换来两个数量级速度。

**Q4: VTK 能做游戏吗？**
> 方向就拧了。VTK 的数据模型是"科学数据集 + Filter 流水线"，
> 没有场景图/物理/动画/资产工作流；Unity 反过来做科学可视化又缺
> 体绘制/Filter 生态。领域不同不构成竞争。

**Q5: 为什么 2018 年实时光追才普及？**
> 三个条件同年凑齐：RT Core 把 BVH 求交做成专用电路（快 10 倍）、
> DXR/Vulkan RT API 标准化（生态可写）、AI 降噪让 1 采样可用
> （DLSS 补帧）。此前算法早已成熟 30 年，卡的是硬件专用化。

## 四、以 LidarAssistant 为例的完整选型复盘（面试可讲素材）

> 需求：桌面工具，实时渲染百万级激光点云，Qt 界面。
> 选型推演：
> 1. 点云 = 只有 points 的 PolyData，无光照/反射需求 → 光追无用武之地，
>    光栅化画点即可
> 2. 百万点每帧 = 纯 fragment 吞吐 → 任何 GPU 都是零头负载
> 3. 场景固定单一 → 不需要引擎，不需要 VTK 的 Filter 体系
> 4. Qt 生态 + 团队可控 → Qt 内置 OpenGL widget，手写 500 行渲染器
> 结论：Qt + OpenGL 手写。如果需求变成"点云 + 医学影像混合可视化"，
> 我会换 VTK（体绘制白送）；变成"照片扫描重建浏览"，上 3DGS。
