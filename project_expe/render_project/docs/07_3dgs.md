# 07 — 球谐函数 + 3DGS：第三条渲染路线

## 一、来龙去脉：从拍照重建说起

**问题**：我绕着一栋建筑拍 200 张照片，能不能让计算机"学会"这个场景，
从任意新角度看都真实？

三代答案：

| 代际 | 技术 | 表示方式 | 渲染方式 | 速度 |
|---|---|---|---|---|
| 2013 | SfM/MVS（传统重建） | 三角网格+贴图 | 光栅化 | 实时，但**糊/破洞**（弱纹理、反光全废） |
| 2020 | **NeRF**（神经辐射场） | 神经网络权重（隐式） | 每像素过 MLP 查询 | 训练数小时/渲染秒级，照片级但**慢** |
| 2023 | **3DGS**（3D Gaussian Splatting） | 数百万个"彩色雪球"（显式） | 雪球投影+排序叠加 | 训练几十分钟/**渲染 100+fps**，照片级 |

3DGS 火爆的根源一句话：**NeRF 的质量 + 光栅化的速度**。
它拿了 SIGGRAPH 2023 最佳论文，两年内成为数字孪生/三维重建/AR 的
工业新宠。理解它需要两个积木：球谐函数 + splatting。

## 二、积木 1：球谐函数（Spherical Harmonics, SH）

### 它解决什么问题（先看需求再谈数学）

现实物体有个麻烦属性：**从不同方向看，颜色不同**。
- 车漆：正对看是红，侧看偏金属白（fresnel 反射）
- 光滑塑料：朝光那面有高光
- NeRF 时代的采样：每个点每个方向都要神经网络输出 → 慢

需要一种**紧凑表示"方向→颜色"函数**的工具——球谐函数。

### 直觉：方向信号的"调频收音机"

回忆傅里叶级数：**任何 1D 周期信号都能拆成一堆正弦波**
（低频管轮廓、高频管细节）。球谐函数就是这句话的 **3D 版**：

> **球面上（所有方向）的任何函数，都能拆成一组"标准球面波"的加权和。**

```
信号      傅里叶（1D 圆周）          球谐（2D 球面）
─────     ──────────────────         ──────────────────
低频项    缓慢变化的基频波            Y₀₀ 常数（整体平均亮度）
中频项    中等频率谐波               Y₁ₘ 一阶（上下左右明暗差）
高频项    高频细波                   Y₂ₘ 二阶、三阶……（细节光泽）
截断      只留前 k 项=低通滤波        只留前 k 阶=忽略高频细节
```

### 实际怎么用（具体到数字）

3DGS 里每个高斯点存 **3 阶球谐系数 × RGB 三通道 = 16×3 = 48 个数**：

```
看这个点时：
  输入视线方向 d（球面上一个点）
  颜色(d) = Σ  系数[i] × 基函数Y[i](d)     ← 16 次乘加，纯数学无网络
```

- 0 阶项 = 基础色（所有方向相同的底色）
- 高阶项 = 修正量（"从上往下看更亮""侧面有反光"）
- **阶数越高表示越精细但越贵**：3 阶够大多数物体，金属/车漆要 4~5 阶

工程直觉：球谐 = "**把'方向相关外观'压缩成 48 个 float 的压缩算法**"。
对比 NeRF：同样信息塞进 MLP 权重（几十 MB，查询要跑网络）——
SH 显式、可微、查询只要 16 次乘加。**压缩换速度，这是 3DGS 的第一根支柱。**

### 球谐的其他出处（知道它在哪等你）

- **环境光照预计算**：游戏引擎把环境贴图转 SH 系数（几个数代替一张
  HDR 图），实时算间接光——Unity/UE 的 light probe 内核
- **PRT（预计算辐射度传递）**：GDC 2002 经典，漫反射全局光预烤
- **量子化学/物理**：原子轨道就是球谐（同款数学，不同领域）

## 三、积木 2：Splatting（泼溅）

光栅化画三角形；splat 画**带颜色的软雪球**：

```
每个高斯雪球 =
  位置 μ (xyz)              ← 在空间哪
  形状 Σ (3D 协方差)        ← 椭球的朝向和压扁程度
  透明度 α                  ← 多不透明
  颜色 = SH 系数(48 个数)   ← 从哪个方向看是什么色
```

渲染一帧 = 四步流水线（全是你在 cuda_project 学过的 CUDA 活）：

```
① 投影：3D 椭球 → 2D 屏幕椭圆（MVP 数学 + 协方差变换）
② 剔除/分桶：屏幕外的扔掉，屏幕内的按 tile（16×16 像素块）分桶
   → 就是 uniform_grid 的 count + scatter！
③ 排序：每 tile 内按深度排序
   → cub radix sort 原题！
④ 泼溅：每 tile 一个 CUDA block（SMEM 缓存高斯参数），
   像素从远到近 α-blend 叠加：
        C = c₁α₁ + (1-α₁)( c₂α₂ + (1-α₂)(...) )
   → smem tiling + 排序 + 混合，cuda_project 三件套全套复用
```

**为什么必须排序**：α-blend 不满足交换律（01 篇的透明排序问题在
这里以百万级规模重现）——这是 3DGS 与光栅化的核心差异：
三角形靠 Z-Buffer 乱序胜出，**高斯必须全局排序**（好在只需 tile 内排，
单 tile 通常几十~几百个高斯）。

## 四、3DGS 怎么训练出来（可微渲染 + 梯度下降）

渲染公式全程可导 → 从"随机雪球"开始，对着 200 张照片迭代：

```
初始：SfM 稀疏点云撒高斯（位置差、全灰色）
循环（可微 splatting 前向 → 和真照片算损失 → 反传梯度更新）：
  位置/形状/透明度/SH系数 逐步更新
  自适应密度化：误差大的地方分裂更多高斯（克隆/分裂），
                透明度太低的删掉
结果：百万级高斯精确复现场景
```

**挂钩 CUDA 知识**：训练就是可微渲染 = 每次 splat forward 是一个
CUDA kernel，反向传播还需要"每个像素收了哪些高斯贡献"的梯度累加——
结构上是 atomic 累加 + 排序的混合负载。3DGS 的开源实现
（graphdeco-inria/gaussian-splatting）核心 CUDA 代码 ~2000 行，
是图形+CUDA 交叉的最好练手项目。

## 五、3DGS vs 光栅化 vs 光追 vs NeRF

| 维度 | 光栅化 | 光追 | NeRF | 3DGS |
|---|---|---|---|---|
| 场景表示 | 显式三角网格 | 显式网格/体素 | 隐式神经网络 | **显式高斯集合** |
| 渲染单元 | 三角形 | 光线 | 每像素 MLP 查询 | 椭圆雪球 |
| 外观模型 | 贴图+shader | 材质 BSDF | 网络直接输出 | **球谐系数** |
| 逼真度 | 依赖美术 | 物理正确 | 照片级 | 照片级 |
| 渲染速度 | 300+ fps | 离线/半实时 | 0.1~1 fps | **100~300 fps** |
| 训练时间 | 不适用 | 不适用 | 数小时 | **几十分钟** |
| 编辑性 | 好（网格可编辑） | 好 | 差（黑盒） | 中（显式但百万个） |
| 动态光 | 好 | 好 | 差 | **差**（烘焙了光照） |

3DGS 的两个短板（面试高频）：
1. **光照是"烤"进去的**：SH 系数把拍照时的光照和材质混在一起，
   换光照要重训练（动态重光照是当前研究热点）
2. **无表面语义**：一堆半透明雪球不是实体表面，碰撞检测/物理
   交互要另外提取 mesh

## 六、什么场景用 3DGS（决策）

用 3DGS，当：
- **照片级 + 实时**看真实场景：数字孪生、房地产 VR、文物数字化、
  AR 背景重建
- 输入是一堆照片/多视角视频（采得到就建得出）
- 视角相关外观重要（反光材质、水面）

不用 3DGS，当：
- 需要重打光/物理仿真 → 传统管线（网格+材质）或可重光照的隐式方法
- 场景是程序生成/美术创作（无照片可拍）→ 光栅化管线
- 极端带宽受限：百万高斯每帧排序+传输，手机端是当前工程前沿问题

## 七、面试讲法（30 秒版）

> 3DGS 是 2023 年的第三条渲染路线：用数百万个带颜色、各向异性的
> 3D 高斯显式表示场景，每个高斯的"方向相关颜色"用 3 阶球谐系数
> 压缩——球谐之于球面方向信号，等于傅里叶之于周期信号，48 个数
> 替代了 NeRF 的整个 MLP。渲染时高斯投影成屏幕椭圆，按 16×16 tile
> 分桶、桶内 radix 排序、从远到近 α-blend——本质是"把光栅化的
> tile 化并行和 CUDA 的排序/smem 流水线"组合起来，所以能实时。
> 训练靠可微 splatting 反传梯度，几十分钟收敛。短板是光照烘焙
> 进 SH 系数无法重打光、没有表面语义。

## 八、自检问答

1. **Q: 球谐函数一句话是什么？**
   A: 球面函数的傅里叶展开——用一组正交基函数加权和表示"方向→数值"，低阶管平均、高阶管细节，截断=有损压缩。
2. **Q: 3DGS 为什么比 NeRF 快两个数量级？**
   A: 表示显式（高斯参数 vs 网络权重）+ 查询是解析数学（16 次乘加 vs MLP 前向）+ 渲染可 tile 化排序并行（vs 每像素独立过网络）。
3. **Q: 3DGS 渲染为什么必须排序，光栅化为什么不用？**
   A: α-blend 不满足交换律，叠加顺序就是视觉结果；三角形用 Z-Buffer 做逐像素最大深度选择，不混合所以乱序无碍。
4. **Q: 高斯的形状参数是什么，怎么投影到屏幕？**
   A: 3D 协方差矩阵（椭球三轴朝向长度）；投影时经视图/投影的雅可比变换得到 2D 协方差（屏幕椭圆），仍按高斯衰减叠加。
