# 02 — 光线追踪：从像素出发"问"世界

## 一、故事导入：为什么反过来就真实了

光栅化伪造反射的破绽（镜子里没有动态物体），根源是它**只处理"眼睛→物体"
这一段**，光在场景里的二次弹射（物体→物体→眼睛）全部看不到。

而真实世界是这样：光源发光 → 弹射 N 次 → 进入眼睛。模拟全过程（正向光线追踪）
99.999% 的光是浪费的（根本不进眼睛）。

**光路可逆原理**救了场：从眼睛反着发光线，只追踪"最终会进眼睛"的光路，
计算量直接砍掉一亿倍。这就是实际使用的光线追踪：

```
眼睛 ──光线──→ 撞到红球 ──反射线──→ 撞到蓝天 ──→ 停！
  ↑                                                  │
  └──────────── 像素颜色 = 沿途所有信息的组合 ←──────┘
  红球这个像素 = 红球本身的颜色 × 反射的天蓝色
```

每条光线递归地问："我撞到了什么？撞到的点又往哪反射/折射？"
——反射、折射、阴影**自然涌现**，不需要任何 shadow map 之类的伪造。

## 二、核心瓶颈：求交（Intersection）

光追 90% 的时间花在"这条光线撞到哪个物体"上。
暴力法 = 每条光线 × 场景每个三角形求交：

- 1080p × 每像素 4 条采样光线 × 每条递归 3 层 = 每帧 ~2400 万条光线
- 场景 100 万三角形 → 每帧 2.4 × 10¹³ 次求交测试 → 不可行

**BVH（Bounding Volume Hierarchy）** 是标准解法——你早就会这个思想：

```
BVH = 把场景三角形装进层层嵌套的盒子
查询一条光线：
  盒子都不相交 → 整棵子树跳过          ← 剪枝
  相交 → 递归查左右子盒
  到叶子 → 只测盒内几个三角形
```

> **挂钩 cuda_project**：这就是空间索引的思想！uniform_grid 是"格子哈希版
> 邻近查询"（近邻搜索），BVH 是"树形版视线查询"（求交）。同一个动机：
> **把 O(N) 全扫降为 O(log N) 空间剪枝**。KNN 用 grid，光线求交用 BVH，
> 因为光线是一条连续射线（树剪枝高效），KNN 是一个点找邻居（格子里圈定）。
> RT Core（下文）就是把 BVH 遍历做成专用电路。

## 三、Path Tracing：更彻底的物理（电影标准）

递归光追仍有"作弊"（只跟踪镜面反射的主光线）。电影级真实感用
**Path Tracing（路径追踪）**：每个像素发射几百条随机光线，
每次弹射方向按材质概率随机采样（蒙特卡洛），弹射 5~8 次统计平均。

- 随机 → 单张图全是噪点
- 每像素几百条采样 → 噪点平均掉
- 一帧电影画面 = 农场渲染 **几小时到几天**
- 2018 后：AI 降噪器（1 采样 + 神经网络去噪 ≈ 传统几百采样效果），
  实时光追游戏（DLSS + 降噪）就靠这个续命

## 四、硬件转折点：RTX 与 2018 年的分水岭

| 年代 | 里程碑 | 意义 |
|---|---|---|
| 1980 | Whitted 递归光追 | 概念确立 |
| 1986 | Kajiya 路径追踪方程 | 理论完备：渲染 = 求解光传输方程 |
| 1990s–2010s | Pixar RenderMan 等离线渲染器 | 电影专属，一帧几小时 |
| 2018 | NVIDIA RTX（Turing 架构） | **RT Core**：BVH 遍历+求交专用电路，求交快 10 倍；**DXR/Vulkan RT API** 标准化 |
| 2018+ | DLSS + AI 降噪 | 1spp（每像素 1 采样）+ AI 去噪 → 游戏实时光追 |

RT Core 到底是什么：普通 CUDA core 也能算求交，但 BVH 遍历是
"判断→跳转→再判断"的串行依赖链，GPU 大规模并行反而低效。
RT Core 是**专门为这个访问模式设计的处理器**（类似 NPU 之于卷积）。

## 五、光栅化 vs 光追：现代引擎的真实答案 = 混合

现代游戏（UE5 Lumen、Cyberpunk 2077 RT 模式）的真相是**混合管线**：

```
一帧画面 = 光栅化画主画面（快，占 70% 时间预算）
         + 光追算全局光照/反射/阴影（贵，选开，占 30%）
         + AI 降噪 + 超分（DLSS）补帧
```

面试时若被问"光追会不会取代光栅化"，标准答案：
**短期内不会，两者是互补分工**——光栅化处理"直接可见"（它已经是最优解），
光追处理"光的二次传播"（光栅化的死穴）。硬件 pipeline 也按此设计。

## 六、什么场景用光追（决策）

用光追/路径追踪，当你的需求是：
- **物理正确**是硬指标：建筑效果图、电影特效、产品广告渲染
- 可以接受**离线**或**半实时**（DLSS/降噪辅助）
- 场景有大量镜面/玻璃/焦散（光栅化伪造不出来的）

不用光追，当：
- 硬实时 + 简单光照模型够用（点云渲染、CAD 线框）→ 光栅化
- 没有显式几何（照片重建的隐式场）→ NeRF/3DGS（07）

## 七、面试讲法（30 秒版）

> 光线追踪利用光路可逆，从相机逐像素发射光线，递归求交和反射来物理正确地
> 累积颜色，反射折射阴影自然涌现，不需要光栅化那套 shadow map 伪造。
> 核心瓶颈是求交，用 BVH 层层包围盒剪枝把 O(N) 降到 O(log N)——和点云
> KNN 的空间索引是同一思想。电影用路径追踪（每像素数百采样蒙特卡洛）离线
> 渲染；2018 年 RTX 把 BVH 遍历做成 RT Core 专用电路加上 AI 降噪，游戏才
> 迈入实时光追。现代引擎实际是混合管线：光栅化画直接可见，光追补全局光照。

## 八、自检问答

1. **Q: 为什么不从光源正向模拟光？**
   A: 绝大多数光不进眼睛，浪费一亿倍；光路可逆允许从眼睛反着追踪。
2. **Q: BVH 和 uniform_grid 各适合什么查询？**
   A: grid 适合"点找邻居"（KNN/散列），BVH 适合"射线找命中"（求交，树形剪枝高效）；本质同属空间索引加速。
3. **Q: RT Core 加速了什么，没加速什么？**
   A: 加速 BVH 遍历+三角形求交（专用电路）；着色计算还是普通 shader core 干。
4. **Q: 路径追踪为什么有噪点，怎么消除？**
   A: 蒙特卡洛随机采样方差大；提高采样数（慢）或 AI 降噪（快，实时代价）。
