# 09 — 渲染概念白话词典 + 流水线全景

> 定位：名词手册。渲染的所有专有名词不是孤立定义，**它们全是流水线上的
> 工位、原料或动作**——按流水线顺序记，比背定义有效 10 倍。
> 建议读完 00 后先过一遍本篇，后面 01/02/06 的细节会自动各就各位。

## 一、总纲：渲染就是"拍照"

屏幕是 2D 的（1920×1080 个小格子），游戏世界是 3D 的。
**渲染（Rendering）= 拍照**：给定场景（物体在哪、光在哪、相机在哪），
算出每个格子该填什么颜色。每秒拍 60 张（60fps），连续放就是动画。

两种"拍照方法"：

| 方法 | 思路 | 类比 | 特点 |
|---|---|---|---|
| 光栅化 | 从物体出发，正向投影到屏幕 | **盖章**：拿三角形往像素格上盖 | 快，游戏 |
| 光线追踪 | 从像素出发，反向询问世界 | **侦探**：每个格子派侦探出去查 | 真，贵 |

## 二、先立流水线，再记名词（地图先行）

光栅化的整条流水线（01 篇的技术版，这里是名词版）：

```
原料区                 ──────── 工厂流水线 ────────              成品区
顶点数据 ──→ ①顶点处理 ──→ ②图元装配 ──→ ③光栅化 ──→ ④片元着色 ──→ ⑤测试混合 ──→ 帧缓冲 ──→ 屏幕
(钉子)      (搬运工)      (组装工)      (盖章工)    (油漆工)      (质检员)      (画布)
             可编程↗                                  可编程↗
          【顶点着色器】                            【片元着色器】
```

每个名词下面按"一个三角形的一生"顺序讲——顺着流水线走一遍全记住。

## 三、名词词典：按一个三角形的一生

### 第 0 站：原料三兄弟

**顶点（Vertex）**
3D 空间里的一个点 (x,y,z)，随身带属性（颜色、法线、纹理坐标）。
类比：物体表面**钉的钉子**。建模师在物体表面钉满几万个钉子。

**三角面片（Triangle / Face）**
三个顶点连起来的一小块平面。类比：钉子之间**拉皮筋蒙皮**。
为什么是三角形不是四边形？三点必共面（四点可能扭曲翘起），
数学最简（重心插值有闭式解），且硬件为此造了 30 年专用电路。

**网格（Mesh）**
几万~几百万个三角面片拼成的物体"皮肤"。一个人体模型 ≈ 10 万个三角形；
3A 游戏一帧 ≈ 数百万个。

**图元（Primitive）**
GPU 能画的基本图形单位：点 / 线段 / 三角形。点云走"点图元"，
普通模型走"三角形图元"。

### 第 ① 站：顶点处理（搬运工）

**顶点着色器（Vertex Shader）**
每**顶点**跑一次的你写的程序。核心任务一件事：**MVP 变换**——
把 3D 坐标搬到屏幕坐标（00 篇讲过 Model/View/Projection 三步）。
类比：搬运工把每颗钉子的"世界位置"换算成"照片上的位置"。

### 第 ② 站：图元装配（组装工）

把每 3 个顶点拼成一个三角形。顺手做**背面剔除**：法线背对相机的
三角形（你看到的盒子内壁）直接扔掉，省一半工作量。

### 第 ③ 站：光栅化（盖章工）——本流水线命名来源

**光栅化（Rasterization）**
判断三角形覆盖了屏幕上哪些格子，并给每个盖到的格子发一个片元。
类比：拿三角形形状的**印章**往像素格纸上一盖。
"光栅（raster）"本义就是屏幕的像素网格——光栅化 = 变成像素网格上的东西。

**插值（Interpolation / varying）**
盖章的同时，把三个顶点的属性"摊薄"给内部每个格子：离哪个顶点近，
属性就偏向哪个顶点（重心坐标加权平均）。三角形中央的格子拿到的是
三个顶点属性的"混血"。这个计算是**硬件电路白送的**。

### 第 ④ 站：片元着色（油漆工）

**片元（Fragment）** —— 全场最容易绕晕的词
光栅化盖到一个格子，就生成一个片元。它是**候选像素**：
位置、插值属性都齐了，但还没通过质检，随时可能被丢弃。

> **实习生类比**：片元 = 实习生，像素 = 转正员工。
> 每个格子门口排着多个实习生（前后几个物体各投来一个片元），
> 只有离相机最近的那个通过面试（深度测试）转正成像素。
> 一个格子可以对应多个片元，也可以片元全被淘汰（格子保持背景色）。

**着色（Shading）**
"算颜色"这件事的学名。一个点最终什么颜色 = 材质（本色）×
光照（光从哪来、多亮）× 视角（从哪看）。把这些因素乘乘加加
得出 RGB 的过程就叫着色。

**片元着色器（Fragment Shader）**
每**片元**跑一次的你写的程序。算光照、取纹理、定颜色——
GPU 算力的最大消耗者（现代游戏 60%+ 时间在这站）。

**纹理（Texture）与纹理坐标（TexCoord）**
纹理 = **贴纸**。与其用十万个三角形拼砖墙细节，不如贴一张砖墙照片。
每个顶点自带纹理坐标（"贴纸位置标签"：u,v），光栅化插值后每个片元
都知道去贴纸的哪个位置取色。

### 第 ⑤ 站：测试与混合（质检员）

**深度测试（Depth Test / Z-Buffer）**
判断谁挡住谁的裁判。每格子旁有个"深度记录本"（Z-Buffer）记着当前
最近物体的距离。新片元来比一下：更近 → 覆盖写入+更新记录；
更远 → 淘汰。神来之笔：物体**任何顺序画都正确**，无需排序。
（细节：现代 GPU 会做 Early-Z——在片元着色前偷跑测试，省掉注定
被淘汰的片元的着色开销。）

**混合（Blending）**
半透明的处理。玻璃后面的东西要看得见，不能只留一个，得按透明度
加权叠加：透过 30% 透明的红玻璃看蓝天 = 0.7×红 + 0.3×蓝。
代价：**必须从远到近排序**（01 篇提过，3DGS 的百万级排序是它的放大版）。

### 成品区

**帧缓冲（Framebuffer）** —— 不止是"颜色数组"

容易误以为帧缓冲就是一块颜色数组。实际它是**三件套容器**——
三块同尺寸、同网格、逐像素一一对应的数组：

```
帧缓冲（Framebuffer）= 容器
├── 颜色缓冲（Color Buffer）    每像素 RGBA      ← 最终送显的"画布"
├── 深度缓冲（Depth/Z-Buffer）  每像素 1 个深度值 ← 深度测试裁判的"记录本"
└── 模板缓冲（Stencil Buffer）  每像素 1 个标记位 ← 掩码特效（只在镜子里画倒影）
```

流水线第⑤站同时写它们：片元转正 → 写颜色 + 更新深度；
模板位用来提前"圈地"决定哪些格子允许画/禁止画。

**模板缓冲展开：屏幕上的"镂空喷漆模板"**

stencil 本义就是美术生的镂空喷漆模板——板子挡住墙，颜料只能从
镂空处穿过。模板缓冲 = 数字版这块板子：每像素 1 个标记位，
标记该格子**允许/禁止被涂色**。

经典案例"镜子里才画倒影"，先理解**为什么会有这个问题**：

- **真实镜子**：光从镜面材料物理弹回，像自动被锁在镜面矩形内——白送的。
- **CG 镜子**：只是一块贴银色贴图的平面，**不会弹光**，渲染器不知道它是
  镜子。想"能照"必须伪造：把物体沿镜面数学翻折一份（湖面倒影和镜子
  倒影是**同一变换**，横放竖放的区别而已），当作普通 3D 模型画到
  "墙后面的世界"里。
- **穿帮根源**：镜像副本是墙后的普通 3D 模型，从相机投影时它的屏幕
  轮廓 **≠** 镜框的屏幕轮廓，没人自动锁边——超界部分会画到墙上：

```
【俯视图】 墙墙墙[镜子]墙墙墙 ← z=0
                │
     真实小明●(z=+2) → 翻折 → 镜像小明●(z=-2, 在墙后)
                │
             相机●(z=+5)

【屏幕上】镜像小明的投影轮廓 ⊃ 镜框轮廓
（你和朋友照小镜子：真实镜子只照到他一条胳膊；
  CG 里他的镜像是个完整的人，投影出一大片，超出镜框的部分
  会直接画到墙上——真实世界那里只有墙，不该有任何像）
```

**镜像副本为什么存在：它就是倒影本身**

它不是倒影的"辅助计算对象"——**它就是要被画上屏幕的倒影本身**：

- **光栅化铁律**：屏幕上每个像素的颜色，只能来自"某个三角形投影
  覆盖了它"，没有任何机制能凭空产生像素。CG 镜子只是一块贴银色
  贴图的平面——它盖住的像素只会被涂成贴图颜色，永远不会自己
  "长出"小明的像。
- **真实镜子白送，CG 必须有人画**：真实镜子的像是光弹射的物理
  结果；光栅化不模拟光（它只是盖章机），所以"镜中像"必须有人
  主动把那些像素画出来。
- **画法依据是平面镜成像定理**：镜中虚像 ≡ 把物体沿镜面翻折到
  镜后。"照镜子看到的"和"墙透明、镜后站着翻折的你"完全一样。
- **视线等价证明**：`相机 → 镜面Q点 → 反弹到真身` 与
  `相机 → 穿过Q → 直达镜像副本`，两条路线落在**同一屏幕像素**。
  所以"翻折 + 当普通物体再画一遍" = 完美倒影，成本只是一次
  矩阵乘法——把"模拟光的反弹"这个贵问题，偷换成"再画一遍几何"
  这个便宜问题，是光栅化骗术哲学的典型操作。
- **舞台类比**：镜中世界 = 墙后搭的另一个舞台。剧组在墙后放了
  一个翻转的布景（镜像副本），观众（相机）透过镜框这扇"窗"看到
  它；模板缓冲只负责把窗口边缘裁齐。

用模板两步修复：

```
Pass 1【圈地】画镜面形状，只写模板不写颜色：
        镜面覆盖的格子 stencil=1，其他=0
Pass 2【限行】画翻转后的物体（倒影），开模板测试：
        "只有 stencil=1 的格子才允许写颜色"
结果     倒影只出现在镜面内；伸出镜子的部分被模板挡掉
```

为什么不在 3D 空间裁剪几何体？又贵又不精确；模板在**屏幕空间**
按像素挡，一行测试指令搞定。同一套路的其他应用：平面阴影
（压扁的假阴影不许穿出地面）、传送门（门内世界只画在门框里）、
轮廓描边（放大一圈先入模板，边缘留白即描边）。

> **工程细节**：镜像物体在墙后，还会被墙的深度挡住——Quake3 经典
> 做法是先用镜框区域清深度缓冲（scissor+clear），再画镜像。
> 另外 RTX 光追时代镜子不需要这套诡计：光线撞镜面会真的递归弹射，
> 镜像是物理免费的（02 篇光栅化 vs 光追的本质差异实例）。

一句话：**模板 = 先圈地、后限行的逐像素许可名单**。

> **交互演示**：[../demos/mirror_stencil.html](../demos/mirror_stencil.html)
> 双视图联动——俯视图看 3D 空间真相（绿楔形=物理可见区、红框=穿帮段），
> 屏幕视图看渲染结果；四模式按钮（穿帮→圈地→限行→最终）+ 拖动小明
> 实时观察镜像伸出镜框。

**帧缓冲是最终产物吗？怎么上屏？**
颜色缓冲确实是这趟管线的终点产物——**显示控制器按行扫描它、
逐像素驱动屏幕发光**。但直接画在"正在显示的画布"上会撕裂
（上半屏旧帧下半屏新帧），所以实际是**双缓冲（Double Buffering）**：

```
GPU 画到【后缓冲】（看不见的画布）
        │  一帧画完，垂直回扫瞬间
        ▼
   交换前后缓冲（swap buffers）──→【前缓冲】送显
```

`SwapBuffers()` / `eglSwapBuffers()` 干的就是这个交换。

> **边界条件**：帧缓冲是"一趟管线 pass 的终点"，未必是"整帧渲染的终点"。
> 现代渲染常有**多级帧缓冲（离屏 FBO）**：先画到离屏缓冲（只存法线/
> 景深/亮度），后处理 shader 在几个 FBO 之间倒腾（模糊/泛光/色调映射），
> 最后一趟才画到上屏缓冲。HDR 泛光、抗锯齿都是这么做的。

**帧（Frame）**
画布的一次完整内容。60fps = 画布每秒被完整重画 60 次。

**管线（Pipeline）**
这条流水线本身。叫"管"因为像水管：数据一头灌入，依次流过各工位，
另一头流出成品。**渲染管线 = 渲染的完整流程**。

## 四、光线追踪的名词（侦探宇宙）

光栅化的死穴：只处理"相机→物体"这一段，光的二次弹射（反射里看到
镜子、玻璃后面的东西）全看不到。光线追踪换方向：

**光线（Ray）**
从相机出发、穿过某个像素的射线——**派出去的侦探**。
光路可逆：与其模拟光源发出的所有光（99.999% 不进眼睛，浪费），
不如从眼睛反着查"什么光会进来"。

**求交（Intersection）**
侦探的核心工作："我撞到哪个物体了？"全场最贵的操作——
暴力法每条光线要和百万三角形挨个测试。

**BVH（层次包围盒）**
查案的**行政区划图**：三角形装进层层嵌套的盒子。查案先查区、
再查街道、最后查户，不用挨家挨户敲门。O(N) → O(log N)。
（和点云 KNN 的 uniform_grid 是同一思想：空间索引加速。）

**反射/折射光线**
侦探撞到镜子/玻璃后，**继续派新侦探**沿反射/折射方向查。
递归进行——反射里的反射里的反射，就是照片级真实感的来源。

**路径追踪（Path Tracing）**
每个像素派几百个侦探**随机**走完整条光路取平均（蒙特卡洛）。
单张图全是噪点（样本太少），几百样本平均后 = 电影级真实。
AI 降噪器让"1 个样本+神经网络去噪"≈ 几百样本，实时光追因此可行。

**RT Core**
把 BVH 遍历+求交做成专用电路的硬件单元（2018 RTX 起）。
"为一种访问模式专门造芯片"——和 NPU 之于卷积同一个套路。

## 五、两种方法对比（盖章 vs 侦探）

| 维度 | 光栅化（盖章） | 光线追踪（侦探） |
|---|---|---|
| 出发点 | 物体投到屏幕 | 屏幕问世界 |
| 单位 | 三角形 → 片元 | 光线 → 求交 |
| 并行性 | 像素独立，天然并行 | 光线独立，天然并行 |
| 真实感 | 靠技巧伪造（shadow map 等） | 物理正确自然涌现 |
| 速度 | 300+ fps | 离线或半实时（RTX+DLSS） |
| 遮挡处理 | Z-Buffer 裁判 | 求交最近命中天生解决 |
| 半透明 | 混合要排序（痛点） | 沿光线积分（顺手） |
| 用户 | 游戏/CAD/点云 | 电影/效果图/新游戏特效 |

现代引擎的真相是**混合**：光栅化画直接可见（已是理论最优），
光追补光的二次传播（光栅化的死穴）。

## 六、全文串讲：一个三角形的一生（10 秒版）

1. 我是模型脸上十万个三角形之一，三个顶点（钉子）带着属性待命
2. **顶点着色器**把钉子搬上屏幕（MVP）——我成了屏幕上的 2D 三角形
3. **图元装配**把三颗钉子拼成我
4. **光栅化**盖章：盖到的每个格子发一张"片元实习生证"，
   顶点属性插值摊薄给每个人
5. 每个片元到**片元着色器**领颜色（算光照、贴贴纸）
6. **深度测试**：更近的物体占了格子 → 我被淘汰；我是最近 →
   转正成像素写入**帧缓冲**
7. 全部格子写完 → 一帧 → 每秒 60 次 → 你看到的游戏画面

## 七、理解心法（三条）

1. **渲染 ⊃ 光栅化**：渲染是"拍照"全过程，光栅化只是其中一站
   （但口语常混用——面试时能分清是加分项）
2. **一切为并行而生**：三角形独立、像素/光线独立 → 几千个工位
   同时开工 → GPU 存在的理由（.cuda 项目的 warp 概念源头就在这）
3. **记名词先问三件事**：它在流水线哪个工位？是原料、动作还是质检？
   它的输入输出是什么？——比背定义有效 10 倍

## 八、面试讲法（30 秒版）

> 渲染是把 3D 场景变换成 2D 像素图像的过程，主流两条路：光栅化从物体
> 正向出发，顶点经 MVP 变换、图元装配成三角形、光栅化成片元、片元
> 着色算颜色、深度测试混合后写入帧缓冲；光线追踪从像素反向出发，
> 递归求交模拟光的传播，反射折射自然涌现。片元和像素的区别是前者
> 是候选（未通过深度测试的半成品），后者是写入帧缓冲的成品。
> 实际引擎是混合管线：光栅化管直接可见，光追管全局光照。

## 九、自检问答

1. **Q: 片元和像素的区别？**
   A: 片元是光栅化产生的候选像素（带插值属性、未过质检）；像素是写入帧缓冲的最终格点。一个格子可对应多个片元。
2. **Q: 为什么用三角形不用四边形？**
   A: 三点必共面、插值有闭式解、硬件 30 年专用优化；四点可能不共面导致扭曲。
3. **Q: 顶点着色器和片元着色器各跑几次、各干什么？**
   A: 顶点着色器每顶点一次做 MVP；片元着色器每片元一次算光照/纹理/颜色，是算力大头。
4. **Q: Z-Buffer 为什么让绘制顺序无所谓？**
   A: 每格子维护最近深度，新片元比近则胜——逐像素贪心，与提交顺序无关。
5. **Q: 光线追踪为什么天然解决半透明，光栅化却要排序？**
   A: 光线沿视线积分天然有序；光栅化的片元来自乱序三角形，混合不满足交换律必须先排。
6. **Q: 插值发生在哪一步、谁做的？**
   A: 光栅化阶段，硬件电路白送：三角形内部属性按重心坐标对三顶点加权。
7. **Q: 帧缓冲只有颜色数据吗？**
   A: 不。它是三件套容器：颜色缓冲（RGBA）+ 深度缓冲（深度测试记录本）+ 模板缓冲（掩码标记位），三块数组逐像素一一对应。颜色只是送显的那一块。
8. **Q: 有了颜色缓冲就能直接上屏吗？**
   A: 还差一步：GPU 画的是后缓冲，画完在垂直回扫瞬间 swap 交换前后缓冲（双缓冲），前缓冲才被显示控制器扫描送显——直接画正在显示的画布会撕裂。
9. **Q: 帧缓冲是整帧渲染的终点吗？**
   A: 只是"一趟 pass"的终点。现代渲染用多级离屏 FBO：法线/景深/亮度各画一趟，后处理链倒腾，最后才画到上屏缓冲（HDR 泛光、抗锯齿的套路）。
10. **Q: 模板缓冲的"镜子倒影"具体怎么工作？**
   A: 两趟画：先把镜面形状写进模板（圈内=1），再画翻转的物体并开模板测试"只有=1 的格子许写颜色"——倒影被限制在镜面内，伸出部分自动被挡。价值：屏幕空间逐像素裁剪，比 3D 裁几何便宜且精确。
11. **Q: 真实镜子自动把像锁在镜面内，CG 的镜像为什么会"伸出"镜框？**
   A: 真实镜像是光从镜面物理弹回，视线不穿镜面矩形就成不了像；CG 镜像是沿平面翻折出的普通 3D 模型（画在墙后），从相机投影的轮廓 ≠ 镜框轮廓，没人自动锁边，超界部分会画到墙上——所以才需要模板圈地。湖面倒影和镜子倒影是同一数学变换，只是平面横竖放的区别。
12. **Q: 为什么要画镜像副本？它是计算倒影用的辅助对象吗？**
   A: 不是辅助——它就是倒影本身。光栅化中像素颜色只能来自覆盖它的三角形，镜子贴图平面永远"长不出"像；平面镜成像定理保证"翻折副本直接看"与"真身经镜面反弹看"逐像素等价，所以画副本 = 画倒影，成本只是一次矩阵乘法。
