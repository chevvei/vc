## 一、岗位到底干什么（一句话故事版）

算法研究员给出数学公式："从这里到那里，生成一万条候选轨迹，挑一条最优的"。
**你的工作**：把这套数学变成跑得快、跑得稳、不撞墙的 C++/CUDA 代码。

故事版：算法同事是"设计师"，画了一张机器人走迷宫的图纸；你是"总工程师"，把图纸变成实物——选好钢筋（数据结构）、浇筑混凝土（CUDA kernel）、装电梯（profiling 工具），保证这栋楼**实时盖完不塌**。

**岗位核心三件事**（按优先级）：
1. **高性能 C++ 框架搭建**：分层解耦、模块接口、日志、测试
2. **GPU 大批量并行数值计算**：采样、梯度下降、约束求解
3. **空间数据结构 + 性能 profiling**：ESDF/KDTree 维护、cache 优化、数值稳定性

**不要求你做的事**：发明新规划算法、推数学公式、写论文。

## 二、运动规划专有名词故事化讲解

### 2.1 运动规划（Motion Planning）是什么

**故事**：你让机器人从 A 点走到 B 点，中间有桌子、椅子、人。机器人不能直接走直线（会撞），要生成一条**无碰撞、满足动力学约束**的轨迹。

**两个核心问题**：
1. **路径**：走什么形状（绕过桌子）
2. **速度/时间**：什么时候到哪（不能突然加速，否则机器人翻车）

**运动规划 = 路径 + 速度 + 约束**，输出一条机器人能执行的轨迹。

### 2.2 采样式规划（RRT / PRM）

**RRT（Rapidly-exploring Random Tree，快速探索随机树）**：
- 故事：蒙眼走迷宫，每次往随机方向伸一根树枝，树枝撞墙就砍掉，没撞就保留，继续从树枝末端再伸。最后长成一棵覆盖整个房间的树，从树根到目标点就是一条路。
- 特点：**随机采样 + 碰撞检测**，适合高维空间（机械臂关节空间）

**PRM（Probabilistic Roadmap，概率路线图）**：
- 故事：先在房间里撒一堆点，能连上的点用线连起来，形成路网；之后任意起终点都查这个路网找路径。
- 特点：**预建图 + 多次查询**，适合静态环境

**GPU 并行采样**：一次性在 GPU 上批量生成几万条候选轨迹，并行做碰撞校验，挑最优的。故事版：一万个蒙眼人同时走迷宫，谁先到终点谁赢，GPU 让这件事瞬间完成。

### 2.3 轨迹优化（Trajectory Optimization）

**故事**：采样得到的轨迹很糙（绕路、抖动），要"打磨"——迭代微调每个点，让轨迹**更短、更平滑、更省时间**。

**怎么打磨**：定义一个**代价函数**（cost function）：
```
总代价 = w1·离障碍物距离代价 + w2·平滑度代价 + w3·时间代价
```
用梯度下降法迭代调整轨迹点，让总代价下降。

**批量梯度下降**：GPU 上同时打磨几万条候选轨迹，每条独立迭代，挑收敛后代价最低的。这就是岗位说的"批量梯度下降"。

### 2.4 约束求解（Constraint Solving）

**约束分两种**：
- **硬约束**：必须满足，违反就出事（不能撞障碍、关节限位、速度上限）
- **软约束**：尽量满足（轨迹平滑、能耗低）

**约束求解**：在"满足所有硬约束"的空间里找最优解。数学上是带约束的优化问题，用 **IPOPT/NLopt/Ceres** 这类求解器迭代求解。

**你的工作**：不推数学公式，但要：
- 看懂求解器接口，把代价函数和约束传进去
- 调性能（求解慢了要优化 Jacobian 矩阵计算、GPU 加速）
- 保稳定（迭代发散、NaN、不收敛要定位）

## 三、空间数据结构（岗位重点考核）

### 3.1 K-D Tree（k 维树）

**是什么**：对 k 维空间点集做**最近邻搜索**的二叉树。每个节点按某一维切一刀，左子树小于切点，右子树大于。

**故事**：你有 100 万个点云点，机器人问"我当前位置最近的 10 个障碍点是谁？"。线性扫描要 100 万次比较，K-D Tree 只需 ~log(100万)≈20 次。

**怎么用**：
- 点云邻域搜索（你雷达项目里做过同类事）
- 障碍物最近邻查询
- 碰撞检测加速

**工程瓶颈**：
- **内存不连续**：树节点指针跳来跳去，cache miss 严重
- 高维时性能退化（k>20 几乎线性扫描）
- 动态插入删除代价高（平衡重建）

**面试一句话**：K-D Tree 是空间二分树，最近邻查询 O(log n)，工程难点是**节点指针跳跃导致 cache miss**，优化方向是**扁平化、缓存友好布局**。

### 3.2 ESDF（Euclidean Signed Distance Field，欧氏符号距离场）

**是什么**：把三维空间切成体素网格，每个格子存一个数——**离最近障碍物的距离**（障碍物内为负，外为正）。

**故事**：给整个房间铺一层"等高线地图"，每个格子标注"我离墙多远"。机器人查这个表就知道：这个点安全吗？梯度方向是哪？比实时算距离快几个数量级。

**用来干什么**：
- **碰撞代价**：轨迹上每个点查 ESDF 得到距离值，距离<0 就是撞了
- **梯度引导**：距离场的梯度方向指向"远离障碍"，轨迹优化时往梯度下降方向调整
- **快速碰撞校验**：O(1) 查表代替 O(n) 计算

**工程瓶颈**（岗位深挖点）：
1. **内存占用巨大**：30m×30m×3m 房间，5cm 分辨率，需要 60万×60万×60 = 3600 万格子 × 4 字节 = 144MB
2. **构建慢**：每个格子都要找最近障碍，朴素算法 O(N·V)
3. **更新贵**：环境动态变化（人走动），要实时重算
4. **访存随机**：查表跳来跳去，cache 不友好

**优化手段**：
- **chunk 分块**：按 16×16×16 块组织，提升局部性
- **GPU 构建**：jump flooding 算法并行计算距离场
- **稀疏存储**：只存障碍物附近的格子，远处用解析公式
- **层级结构**：粗分辨率 + 绑分辨率混合

**面试一句话**：ESDF 是体素距离场，每个格子存到最近障碍距离，规划器 O(1) 查表得碰撞代价和梯度，工程难点是**内存占用大、动态更新慢、cache 不友好**，优化靠**分块、GPU 并行构建、稀疏存储**。

### 3.3 KDTree vs ESDF（容易混淆，重点区分）

| 维度 | K-D Tree | ESDF |
|------|----------|------|
| 数据形式 | 离散点集 | 体素网格场 |
| 查询类型 | 最近邻点 | 任意点距离值 |
| 适用场景 | 点云、稀疏障碍 | 连续空间、稠密场景 |
| 更新成本 | 中（重建子树） | 高（重算整个场） |
| 内存 | 节点指针 | 体素数组 |
| Cache | 差（指针跳） | 中（数组连续但跨度大） |

## 四、计算机体系结构（高频面试）

### 4.1 Cache Locality（缓存局部性）—— 必考

**是什么**：CPU 读内存很慢（~100ns），读缓存快（L1 ~1ns）。数据被载入 cache 后，**邻近的数据大概率一起被访问到**，这就是局部性。

**两种局部性**：
- **空间局部性**：地址相邻的数据大概率接下来被访问（数组顺序遍历）
- **时间局部性**：刚访问过的数据大概率还会被访问（循环变量）

**故事**：你读书，桌子就是 cache，书架是内存。一本本挨着读（空间局部性）很爽；每读一页就跑书架换一本（随机访问）累死。**随机访问会让 cache miss 飙升，性能掉 10~100 倍**。

**优化手段**：
1. **AoS → SoA**：把同一类字段挨着放（见下节）
2. **内存对齐**：数据按 32/64 字节对齐，不跨 cache 行
3. **顺序遍历**：避免 `random[idx[i]]` 这种间接访问
4. **数据压缩**：用更小类型（float→half）让更多数据进 cache

**面试一句话**：cache locality 是 CPU 缓存命中率，随机访问会导致 cache miss 性能暴跌；优化靠**数据连续排布、SoA 布局、内存对齐、顺序遍历**，和你点云优化思路完全一致。

### 4.2 AoS vs SoA（数据布局，必考）

**AoS（Array of Structures，结构体数组）**：
```cpp
struct Point { float x, y, z; };   // 每个点一个结构体
Point points[N];                    // 数组
// 内存：x y z | x y z | x y z ...
```

**SoA（Structure of Arrays，数组结构体）**：
```cpp
struct Points {
    float x[N];   // 所有 x 挨着放
    float y[N];
    float z[N];
};
// 内存：x x x ... | y y y ... | z z z ...
```

**对比**：
| 布局 | 优点 | 缺点 | 适合 |
|------|------|------|------|
| AoS | 一个对象字段全在一起，访问对象所有字段 cache 好 | 只访问某字段时把不相关字段也载入 cache，浪费 | 实体游戏、OOP |
| SoA | 只访问某字段时 cache 命中率满分 | 访问多个字段要跳多个数组 | 数值计算、SIMD |

**故事**：
- AoS：每本书挨着放，找一本书所有内容（x,y,z）都在，但你要算所有书的页数（只访问 y）就得翻每本书
- SoA：把所有书的"页数"单独抽出来挨着放，算总页数顺序遍历 cache 满分

**面试一句话**：AoS 适合访问对象所有字段，SoA 适合批量访问单一字段；运动规划里批量算距离只访问 x/y/z，**用 SoA 提升 cache 命中率和 SIMD 向量化**。

### 4.3 SIMD（单指令多数据）—— 必考

**是什么**：CPU 一条指令同时处理多个数据。比如 AVX2 一条指令同时算 8 个 float。

**故事**：普通 CPU 指令像一个人一次搬一块砖，SIMD 像一台叉车一次搬 8 块。同样搬 1000 块砖，叉车 125 趟，人力 1000 趟。

**适合什么**：
- ✅ 简单、独立、批量运算：距离计算、向量加减、点积
- ✅ 数据连续排布（SoA）
- ❌ 复杂分支逻辑（if-else 多）
- ❌ 数据散乱（AoS、随机访问）

**示例**：
```cpp
// 8 个点距离平方和，AVX2 一条指令搞定
__m256 x = _mm256_load_ps(px);   // 一次载入 8 个 x
__m256 y = _mm256_load_ps(py);
__m256 r = _mm256_mul_ps(x, x);  // 8 个 x² 同时算
// 一条指令算完 8 个点，比循环快 8 倍
```

**什么时候用**：空间距离批量计算、碰撞检测、ESDF 查询批量点。

**面试一句话**：SIMD 单指令多数据，一条指令同时算 8/16 个 float；适合**批量、独立、连续**的数值运算；要用 SIMD 必须保证数据 SoA 布局 + 顺序访问。

### 4.4 内存对齐（Memory Alignment）

**是什么**：数据起始地址是 32/64 字节的整数倍，避免一次访问跨两个 cache 行。

**故事**：搬家公司一次搬一箱（cache 行 64B），东西正好放满一箱效率最高；如果东西横跨两箱，要搬两次。

```cpp
struct alignas(32) PointBlock {    // 32 字节对齐
    float x[8];
};
```

## 五、GPU CUDA 专有知识（你已有基础，串场景即可）

### 5.1 SIMT 模型（GPU 并行模型）

**是什么**：GPU 上大量线程同时执行同一个 kernel 函数，叫单指令多线程。

**故事**：一个教官（kernel）对着一个团（几千线程）喊"齐步走"，所有人同时走，但每个人走的位置不同（不同数据）。

**与 SIMD 区别**：SIMD 严格同步，SIMT 允许线程分支（warp 内尽量不分支否则串行）。

### 5.2 GPU 内存层级（性能优化核心）

| 层级 | 速度 | 容量 | 用法 |
|------|------|------|------|
| Register | 最快 | 几 KB | 线程私有变量 |
| Shared Memory | ~20 倍慢于 reg | 几十 KB | block 内共享，缓存复用 |
| Global Memory | 慢 100 倍 | 几 GB | 全局数据，CPU 拷贝过来 |

**核心优化思路**：
1. 减少全局内存读写（搬数据慢）
2. 用 shared memory 缓存复用（tile 分块）
3. 减少 CPU↔GPU 数据拷贝（PCIe 慢）

**故事**：寄存器是你口袋（秒拿），shared memory 是桌子（快拿），global 是仓库（要等叉车）。优化就是**少跑仓库**。

### 5.3 thrust / cub / cutlass（CUDA 生态库）

- **thrust**：GPU 版 STL，`thrust::sort`、`reduce`，写起来像 C++ 标准库
- **cub**：低层 GPU 原语，block reduce/scan，性能极致
- **cutlass**：矩阵乘法库，模仿 cuBLAS 但可定制

**你的态度**：知道存在、用得上、不深挖原理。需要批量 reduce/sort 时用 thrust，写 kernel 优化用 cub。

### 5.4 GPU 采样式规划（cuRobo 简介）

**cuRobo** 是 NVIDIA 开源的 GPU 运动规划库：
- 把整条规划流水线搬到 GPU：批量采样候选轨迹 → 并行碰撞校验 → 批量梯度下降优化
- 一次几万条候选并行算，毫秒级出结果

**面试提一句**：知道 cuRobo 是 GPU 端到端规划库，理解它"批量采样 + 并行校验 + GPU 优化"的思路即可，不深挖。

## 六、数值优化库（看懂接口，不推公式）

### 6.1 Eigen（C++ 矩阵库）

**是什么**：C++ 线性代数库，矩阵运算，header-only。

**用在哪**：所有数值计算的地基，写矩阵乘法、向量运算、解线性方程组。

**示例**：
```cpp
#include <Eigen/Dense>
Eigen::Vector3f p(1, 2, 3);
Eigen::Matrix3f R = Eigen::Rotation2D3f(...);
Eigen::Vector3f p2 = R * p;   // 旋转后坐标
```

### 6.2 Ceres / g2o（非线性最小二乘）

**是什么**：求解 `min Σ‖f(x)‖²` 这类问题，轨迹优化核心。

**故事**：你有一条粗糙轨迹，每个点位置有误差，想让总误差最小。Ceres 自动求导、迭代、收敛到最优解。

**你做什么**：
- 定义代价函数（残差）
- 配置求解器参数
- 调用 `Solve()` 拿到优化后轨迹
- 关注收敛性、速度，不深挖数学

### 6.3 IPOPT / NLopt

**是什么**：通用约束优化求解器。IPOPT 用内点法，NLopt 支持多种算法。

**用在哪**：硬约束优化（关节限位、速度上限下的轨迹优化）。

## 七、Profiling 工具（你的优势区）

| 工具 | 平台 | 用途 |
|------|------|------|
| perf | Linux | CPU cache miss、分支预测、热点函数 |
| VTune | Intel | Intel CPU 深度剖析、内存带宽、cache 分析 |
| Nsight | NVIDIA | GPU kernel 耗时、显存带宽、线程阻塞 |

**核心方法论**：
1. 用 profiler 定位瓶颈（不是猜）
2. 80% 时间在 20% 代码，先优化热点
3. 改完跑 benchmark，验证是否真提升

**故事**：你车开得慢，别瞎改零件。先用仪表盘（profiler）看是发动机慢（CPU）还是轮胎打滑（cache miss）还是油路堵（访存），定位了再修。

## 八、数值稳定性（容易忽略但岗位必问）

### 8.1 为什么会出问题

**浮点数迭代**：轨迹优化每次迭代小数累加，误差累积、除零、log 负数，最后 NaN/inf。

**常见坑**：
- 除零：`1.0 / 0.0 = inf`
- log 负数：`log(-1) = NaN`
- 大数减小数：`1e10 + 1e-5` 后者丢失
- 梯度爆炸：迭代发散，值越来越大

### 8.2 怎么保障

1. **单元测试**：覆盖边界 case（零向量、共线点、退化配置）
2. **数值检查**：关键函数加 `isfinite()` 检查
3. **迭代上限**：防止死循环
4. **benchmark 监控**：性能退化报警

## 十、面试问答模板（背诵版）

### Q1：为什么没做过 ESDF/KDTree，能维护这类空间数据结构？
> 我在雷达项目做过大量三维点云空间索引、邻域查找、碰撞判断。ESDF/KDTree 本质是空间查询结构，**工程难点都是内存布局、减少随机访问、提升 cache 命中率**。我写高性能代码会主动关注 cache 局部性、内存对齐，能快速上手维护、调优这类模块。

### Q2：GPU 并行采样、批量梯度下降怎么上手？
> 迈瑞项目做过 CUDA 大批量并行数值计算、迭代空间变换，手写 CUDA 算子，重点优化 GPU 访存模式。GPU 并行采样/批量梯度下降本质：GPU 上一次性跑大量候选样本，并行计算代价、梯度、约束校验。**公式由算法同学提供，我的工作是工程实现、内存优化、kernel 延迟、数值稳定**，这是我长期做的。

### Q3：运动规划软件框架搭建怎么理解？
> 核心是分层解耦底座：环境表达（ESDF/KDTree）、采样、约束求解、日志、测试互相隔离，定义清晰接口。我之前 LidarAssistant、UDS DoIP 中间件就是从零搭建这种底层框架：配置驱动、分层架构、抽象接口、日志诊断、单元测试，**这套框架设计思路可以复用**。

### Q4：Cache locality 是什么，怎么优化？
> CPU 访问内存很慢，数据载入 cache。**空间局部性**：相邻内存大概率连续访问；随机访问造成大量 cache miss 性能暴跌。优化手段：**数据连续存放、顺序遍历；用 SoA 代替 AoS；内存对齐；减少随机访问**。

### Q5：SIMD 是什么，适合什么场景？
> 单指令多数据，CPU 一条指令同时算多组 float。适合**简单、批量、独立**的运算，比如距离计算、碰撞检测。要用 SIMD 必须保证数据 SoA 布局、顺序访问，否则没有收益。

### Q6：ESDF 是什么？工程瓶颈在哪？
> ESDF 是体素距离场，每个格子存到最近障碍的距离。规划器 O(1) 查表得碰撞代价和梯度。工程瓶颈：**内存占用大、动态更新慢、cache 不友好**。优化靠**分块、GPU 并行构建（jump flooding）、稀疏存储、混合分辨率**。

### Q7：CUDA 内存层级？优化思路？
> Register 最快、Shared 次之、Global 最慢。优化核心：**减少 global 读写，用 shared 复用，减少 CPU-GPU 拷贝**。具体手段：tile 分块复用、合并访存、减少 PCIe 拷贝。

### Q8：AoS vs SoA 区别？什么时候用 SoA？
> AoS 是结构体数组，访问对象所有字段 cache 友好；SoA 是数组结构体，批量访问单一字段 cache 友好。运动规划批量算距离只访问 x/y/z，**用 SoA 提升 cache 命中和 SIMD 向量化**。

## 十二、一句话总结每个概念

| 概念 | 一句话 |
|------|--------|
| 运动规划 | 起点到终点，生成无碰撞、满足约束的轨迹 |
| RRT/PRM | 采样式规划：随机生成候选路径再筛选优化 |
| 轨迹优化 | 迭代微调轨迹，让代价（距离+平滑+时间）最小 |
| 约束求解 | 在硬约束空间里找最优解，用 Ceres/IPOPT |
| K-D Tree | k 维空间二分树，最近邻查询 O(log n) |
| ESDF | 体素网格，每格存到最近障碍距离，O(1) 查碰撞代价 |
| Cache locality | 数据局部性，连续访问 cache 命中率高 |
| AoS/SoA | 结构体数组 vs 数组结构体，SoA 利于 SIMD 和 cache |
| SIMD | 单指令多数据，一条指令同时算多个 float |
| CUDA SIMT | GPU 单指令多线程，大量线程并行执行 kernel |
| thrust/cub | CUDA 生态库，sort/reduce/scan |
| Ceres/g2o | 非线性最小二乘求解器，轨迹优化核心 |
| perf/VTune/Nsight | CPU/GPU profiler，定位瓶颈 |
| 数值稳定性 | 浮点迭代防 NaN/inf，靠测试和监控 |
